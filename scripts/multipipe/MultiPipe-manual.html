MultiPipe 1.0.0

Turn a network of curves into one solid pipe frame, inside MoI, in a single step.

MultiPipe is no longer being developed. 1.0.0 is its final version: it stays available and keeps working, but it gets no new features and no fixes. For new work, use MultiPipe2, which installs beside it under its own name. A shorter overview and the version history are in the README.

MultiPipe sweeps a pipe along every curve you select, puts a joint where struts meet, and unions everything into one closed solid. Your input curves are kept. The whole result is a single undo step.

Install

MultiPipe is a MoI command: installing it is copying files. Nothing has to be downloaded or run in the background.

  1. Copy these files into your MoI commands folder:
    • MultiPipe.js
    • MultiPipe.htm
    • MultiPipePlanner.js
    • MultiPipeBuilder.js
    The commands folder is %APPDATA%\Moi\commands\ on Windows (e.g. ...\AppData\Roaming\Moi\commands\). On macOS it is <MoI application support folder>/commands/.
    If you prefer, the commands folder inside the MoI install (<MoI install folder>\commands\) works too, but a command kept in %APPDATA% survives a MoI upgrade, so it does not need reinstalling.
  2. Restart MoI.
  3. Type MultiPipe on MoI's command line and press Enter.

Optional: a shortcut key

In MoI, open Options → Shortcut keys, add an entry, put the key you want in the left column and MultiPipe in the right column. The same name works on a custom toolbar button.

MoI caches a command script the first time it runs. If you replace the files with a newer copy, restart MoI.

Running the command

  1. Select the curves. If curves are already selected when you start the command, they are used straight away. Otherwise you are asked to pick them: “Select curves for MultiPipe, then press Done”. Only curves are picked up; solids, surfaces and points in the selection are ignored.
  2. Set the options in the command panel (“Set the options, then press Done”) and press Done. Your values are remembered for the next run.
  3. Wait for the build. The panel shows “Building n struts...” while MoI works. On a large frame the union takes a while and MoI will not repaint during it; this message is there so you know it has not hung.
  4. Read the summary and press Done to add the pipe frame to your document, or Cancel to add nothing. Nothing reaches the document before that last Done, so pressing Cancel at any point leaves your model untouched.

One Ctrl+Z removes the whole result.

Options

OptionDefaultWhat it does
Strut radius0.5 The radius of each pipe, as a distance in your document units. Must be greater than zero. Large radii on short struts can make a strut impossible to build.
Node size1.2 The ball joint's radius as a multiple of the strut radius, so joints scale with the pipe whatever your units are. Values below 1.02 are raised to 1.02, because a ball no bigger than the pipe gives an unreliable union.
Joint styleBall (Filleted off) Off: each joint is a ball slightly larger than the struts — the fast, reliable style. On: the creases around the joints are rounded with a fillet.
Fillet factor0.2 Only shown when Filleted is on. The fillet radius as a fraction of the strut radius. Must be greater than zero. A large factor is more likely to fail; if the fillet fails, the whole frame keeps its ball joints.
CapOn On: free ends are closed with a flat cap, so the result is a closed solid you can export for printing. Off: free ends are left open as tube ends, the rest of the frame still one body.

What MultiPipe does with your curves

  • Lines and smooth curves become one strut each; a polyline becomes one strut per segment, with a joint at every corner.
  • Nodes. Curve ends closer together than the document tolerance count as meeting at one node. Any node where two or more struts meet gets a joint, including nodes of three, four, five, six or more struts.
  • Straight nodes. Where exactly two struts meet with a bend under 5°, no joint is made: the pipe runs straight through as one continuous strut. The 5° threshold is fixed.
  • Free ends. A strut end touching nothing is a free end, capped or open per the Cap option.
  • Closed curves (a circle, a closed freeform curve) become a closed ring pipe with no nodes and no free ends.
  • Duplicate curves — same ends in either direction and the same shape between them — are dropped, and counted in the summary.
  • Crossings — two curves passing through each other without sharing an end — are left unjoined and warned about. See Known limits.

Summary

The first summary line always reads, for example, “12 struts, 5 joints, 2 straight nodes, 4 free ends”: how many pipes were built, how many joints filled, how many nodes the pipe ran straight through, and how many ends were left free. Further lines appear only when they apply:

LineMeaning
n duplicate curve segments dropped. Your selection contained curves lying on top of each other. Only one of each was used.
n crossings left unjoined. Curves pass through each other mid-span. Those pipes intersect but are not joined at the crossing. A warning line names each one.
Joined by the slower step-by-step union. The one-shot union did not produce a complete solid, so the frame was rebuilt joint by joint. The result is a normal complete solid; this line is just why it took longer.
Free ends left open. Cap was off and the cap faces were successfully removed.

Warnings

WarningWhat to do
Curves cross without sharing an end near (x, y, z); left unjoined. Nothing, if you meant them to pass through. To have them joined, split both curves at that point and run MultiPipe again.
The filleted joints could not be made, so the pipe frame kept its ball joints; try a smaller fillet factor. Lower the fillet factor and run again, or keep the ball joints. The fallback is for the whole frame, so you always get one predictable result.
The free ends could not be opened, so the pipe frame was left capped. The result is a valid closed solid; the cap faces could not be identified and removed. Delete them by hand if you need open ends.
The union did not give one solid, even after a retry; struts and joints were kept as separate objects. The struts and joints are still added, so no work is lost. Union them by hand, or nudge the awkward node and run MultiPipe again.

Known limits

  • Crossings are not split. Curves that pass through each other mid-span are warned about and left unjoined. Split them yourself where you want a node.
  • The fillet fallback is whole-frame. If the filleted joints fail anywhere, the entire frame keeps its ball joints rather than a mixture.
  • Filleted joints are slow on large frames. A dense frame has hundreds of joint edges, and filleting them can take minutes. Ball joints are the practical choice for large frames; fillet a small frame first to find a factor that works.
  • No wall thickness. The pipes are solid, not hollow tubes.
  • No live preview. You see the result after the build, before committing it.
  • One radius for the whole frame. No per-node or variable strut size.
  • The straight-node threshold is fixed at 5° and is not an option.

What has been tested, and what has not

This is a first release. The geometry is well covered by automated tests; the command panel is not, because MoI's command panel cannot be driven by a script — only by a person at the keyboard.

Tested automatically, on every change: the planning — which curve becomes which strut, where nodes are, straight nodes, closed curves, duplicates, crossings — and the geometry, by building 26 test frames inside MoI and checking each result: the ball joints, the union and its step-by-step retry, the filleted joints and their fallback, capped and open ends, and a 300-strut frame.

Not covered by any automated test, so worth a careful first look:

Curves picked in a live document The step that turns your selection into struts: ignoring the non-curve objects in a selection, and splitting a joined multi-segment curve. The tests build their curves rather than picking them.

Nothing reaches your document until the final Done, and one Ctrl+Z takes back what it added — so trying it costs you a keystroke. Save your work first anyway, and please report whatever you find.
